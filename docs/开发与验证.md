## 环境与检查

源码构建使用 JDK 17、Gradle wrapper、Android SDK（compileSdk 36）；iOS 需要 macOS/Xcode，HarmonyOS HAR 需要匹配 API 22 的 DevEco SDK、ohpm 与 hvigorw。先配置 `ANDROID_HOME` 和 HarmonyOS 工具链路径，命令从仓库根目录运行；以下是维护者检查命令，不是第三方安装步骤。

```sh
bash gradlew :scanner-core:compileDebugKotlinAndroid :scanner-core:compileKotlinIosSimulatorArm64 :scanner-core:compileKotlinOhosArm64 :scanner-kuikly:compileKotlinOhosArm64
xcodebuild -scheme GycScannerNative -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build
node tests/scanner.cjs
bash gradlew -p verification compileDebugKotlinAndroid compileKotlinIosSimulatorArm64 compileKotlinOhosArm64
```

HarmonyOS HAR 在 `ohos/` 内执行：

```sh
ohpm install --all
hvigorw --mode module -p module=ScannerNative@default -p product=default assembleHar --no-daemon
```

需要 SDK 的检查只在对应环境执行；不默认 `clean` 或全仓库构建。独立消费者使用 README 的远程 Maven 坐标，不使用 `mavenLocal` 或源码 `project/includeBuild` 替换。

## 已有验收与限制

[0.1.1 Release](https://github.com/gycrosskit/scanner/releases/tag/0.1.1) 记录完整 Maven 产物、独立远程 Android/OHOS 编译和 iOS Simulator Framework 最终链接，以及远程 Swift Package 构建。Node 检查实际 ArkTS 逻辑的并发、取消、权限错误和临时文件清理。本轮文档修改没有重跑这些检查。

2026-09-30 文档核对：Maven `0.1.1` 的根 artifact POM 可从 JitPack 读取，JitPack 构建状态 `ok`；[OHPM registry](https://ohpm.openharmony.cn/ohpm/@gycrosskit%2Fscanner-native) 的 versions/latest 包含 `0.1.1`。这只是当前远程元数据/文档核对，未执行新的安装、构建或设备测试。旧 Release 中“审核中/404”描述是当时状态，现行安装版本以 README 和 registry 为准。

编译、链接、契约测试和远程 metadata 不代表真实设备验收。系统权限弹窗、相机或定位能力、系统页面、前后台生命周期、多窗口和内存边界需按本库实际能力在宿主设备检查。

## Maven 产物维护

Maven Android/iOS/OHOS（按本库实际 target）产物在 macOS 生成并放入版本化 Release 归档；JitPack 下载对应不可变标签的归档，校验 SHA-256 后安装。源码检查不能替代完整 KMP `.module` 与每个引用产物的检查；本地 Maven 验证不能替代默认远程消费。标签、归档与校验和不得覆盖，Maven 二进制不提交到源码仓库。

完整发布步骤与不可变产物约束见 [GY CrossKit 发布流程](https://github.com/gycrosskit/.github/blob/main/docs/发布流程.md)，历史版本见 [发行页](https://github.com/gycrosskit/scanner/releases)。
