# 0.1.6 跨端行为候选（未发布）

`scanner-kuikly` 新增 Android/iOS publications，与 OHOS 共用正式 `ScannerPreviewView/Attr/Event` 协议及 Kuikly Compose `ScannerPreviewHost`。宿主不再需要复制这些协议类；继续注册 `GycScannerPreviewView`，Android 注册 View 委托 `scanner-core.ScannerPreviewView`，iOS 委托 Swift `ScannerPreviewView`，OHOS 注册 HAR View。库不复制三套相机，也不维护第二个业务 scanner state。

Host 参数为 `running/onResult/onFailure/modifier/scanFrameSize/onFeedback`，默认 frame 260dp；使用最新 callback 和 running 门禁。原生节点负责一次结果后停止、暂停可恢复、节点销毁终态释放；宿主负责权限、业务结果、取景框和按钮等 UI。CMP 保持 View/Swift UIView 平台入口，由宿主共同 scanner state/UI 装配；本仓未提供 CMP common Composable，也未声明扫描页面视觉已完全对齐。

统一反馈默认关闭。Kuikly Compose 的 `onFeedback` 与 Android/iOS native 的 `setFeedbackHandler` 在一次有效结果上调用一次；Kotlin 异常不丢结果，Swift callback 不抛异常，release 清引用。Android `setFeedbackEnabled` 的原生音色/振动仍是可选 extension；启用宿主统一反馈时关闭该 extension，避免双响。蜂鸣、文案和业务导航的最终策略由宿主提供。

图片解码/system ScanKit `ScannerModule` native 配套仍为 OHOS；Android/iOS 用 core/Swift 解码能力。OHOS native 源码未修改，配对 HAR 保持 0.1.3；Swift 新 feedback API 需 tag 0.1.6。新 Maven 共 12 publications（新增4个 Kuikly A/i），公开 UI/Core 类型使用 api 依赖。

验证：Android preview/feedback 回归、Kuikly Compose A/i/O 真实编译、Swift typecheck和独立本地 Maven UI consumer 通过。新版本远程 consumer 必须启用 `-PverifyUnifiedUi=true`；旧已发标签 baseline 不启用新探针。未发布、未真机相机/视觉/声音验收。
