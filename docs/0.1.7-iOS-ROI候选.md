# 0.1.7 iOS ROI 修复候选（未发布）

0.1.6 的 `ScannerPreviewView.setRunning(true)` 先启动 capture session，再异步更新识别区；delegate 当时只检查 running/释放状态。默认全图 ROI 的框外首帧可能被当作唯一结果，停止这一轮扫描。

本候选关闭这一窗口：有效 ROI 设置到 AVCaptureMetadataOutput 后才允许结果；布局为空、框尺寸改变、暂停或释放都会关闭结果入口。异步 ROI 配置绑定启动代次，旧配置不能重新开启新一轮入口。delegate 只接受当前 output 的二维码、非空文本、有限 bounds 与当前 ROI 的正面积交集，忽略框外对象后继续选择本批第一个有效对象；有效结果仍只交付和反馈一次。相同框尺寸重复更新不撤销已就绪 ROI。公开 API 和静态图片解码不变。

保留 Apple `rectOfInterest` 的 intersection 规则，部分相交仍可接收；没有加入 metadata timestamp 限制，因为 AVMetadataObject.time 可以无效。本修复不承诺验证旧 capture 跨 restart 的时间语义。Android 的 YUV 裁剪、iOS 的 AVFoundation ROI、OHOS 的矩形中心/缺矩形回退仍各遵循现有能力；未更改 ScanKit 算法或推断 px/vp 单位等价。

## 最小验证

从仓库根运行（macOS/Xcode，需要可用 iPhone Simulator）：

```bash
python3 tests/run-scanner-roi.py /tmp/scanner-roi-fixed
# 检出包含原 0.1.6 commit 的仓库；预期失败，用于证明旧生产 delegate 的回归：
python3 tests/run-scanner-roi.py /tmp/scanner-roi-baseline --baseline
```

脚本把生产 View 的原字节与同文件 fixture 拼接，直接编译、安装、执行 UIKit App；不复制接收判定，也不新增生产测试 API。fixture 使用真实 AVFoundation 类型及生产 delegate，metadata 为受控子类、ROI 为受控私有状态，所有 metadata timestamp 故意无效。检查启动未就绪、框外、一次交付、部分相交、暂停、释放、尺寸变更、相同尺寸、不同 output、本批跳过框外对象；不启动真实相机、不代表设备首帧复现或视觉验收。

候选 Maven / Swift Package 同为 0.1.7；Maven 保持 12 publications，SPM 产品仍为 GycScannerNative。OHOS native 源码未改，HAR 继续配对 0.1.3。PR 的远程消费基线仍固定已发布 0.1.6；本候选归档和本地检查不能当作新版本已远程发布。
