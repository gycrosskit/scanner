## Gradle 与工具链

根 README 列出远程安装坐标。本库 KMP 产物使用 Kotlin `2.2.21-1.0.0`；OHOS target 必须使用兼容的厂商工具链。项目构建使用 Gradle `8.11.1`、AGP `8.10.1`、Android compileSdk `36`，Gradle 运行使用 JDK 17。源码的 Java/JVM 编译目标与运行 Gradle 的 JDK 是不同要求。

在 `settings.gradle.kts` 中为 Kotlin 插件与依赖分别配置仓库；保留宿主已有仓库：

```kotlin
pluginManagement {
```

Kuikly 模块使用 `2.28.0-2.0.21-ohos`。Swift Package、OHPM HAR 和 Maven KLIB/AAR 分别安装，Maven 不替代原生依赖或宿主桥接。HarmonyOS 包的 `targetSdkVersion` 和 `compatibleSdkVersion` 均为 `6.0.2(22)`，不据接口 API 级别推断当前 HAR 可运行于更低系统。

## Android

`AndroidQrCodeDecoder.decode(bytes)` 在后台线程解码，未识别或无效图片返回 null。相机预览使用 `ScannerPreviewView`，先申请 CAMERA 权限，再在主线程启动。每次启动只投递一次结果；结果后需要再次显式 `setRunning(true)`。

可选 `setScanFrameSize(pixels)` 要求正值，单位为像素。Compose 的 `AndroidView` 可承载控件；根据宿主前后台/权限状态更新 `setRunning`，`onRelease` 调用 `release()`。普通 View 宿主在 onPause 暂停，永久销毁释放。AAR 合并 CAMERA 声明；设备错误经 `onFailure` 返回。

## iOS 原生与 KMP

Swift Package 安装见 README。宿主申请相机权限并填写 `NSCameraUsageDescription`，所有预览操作在主线程：

```swift
import GycScannerNative
let text = QrCodeDecoder.decode(data: imageData)
let preview = ScannerPreviewView(onResult: { text in
    // 宿主校验原始文本。
}, onFailure: { reason in
    // 宿主展示失败。
})
preview.setRunning(true)
// 页面离开或进入后台：
preview.setRunning(false)
// 永久销毁：
preview.releaseCamera()
```

图片解码可由宿主移至后台队列。`setScanFrameSize` 使用点作为单位。KMP 宿主导出 `scanner-core` 到自己的 Framework，实现 `IosQrCodeBridge.decode(data:)`，委托给 `GycScannerNative.QrCodeDecoder.decode(data:)`，再构建 `IosQrCodeDecoder(bridge)`。Swift 产品与预览不依赖宿主 Framework 名称。

## HarmonyOS 原生与 Kuikly

安装 OHPM 后：

```typescript
import { GycScanner } from '@gycrosskit/scanner-native';
const scanner = new GycScanner(context);
const result = await scanner.scan();
const decoded = await scanner.decode(imageArrayBuffer);
// 页面销毁：
scanner.dispose();
```

`context` 为当前 `UIAbilityContext`。返回 `status` 为 `decoded / not_found / cancelled / permission_denied / busy / invalid_content / failed`，成功文本在 `value`。系统扫码页由 ScanKit 管理，依赖设备 SDK 能力；同实例仅一个扫码请求。dispose 后返回 cancelled，ScanKit 不提供主动关闭系统页接口。图片解码上限 32 MiB，临时文件在 finally 删除。

Kuikly Kotlin Pager 注册 `ScannerModule.NAME to ScannerModule()`（包 `io.github.gycrosskit.scanner.kuikly`）；ArkTS render 注册 `GycScannerModule.MODULE_NAME` 对应 `GycScannerModule`。Kotlin `scanCode()` 取消返回 null，SDK 错误抛异常；`decode(bytes)` 未识别返回 null。页面销毁时显式 `dispose()` 取消挂起请求和移除回调。Base64 桥增加内存开销。

本库无独立图片选择器；ScanKit 系统页是否显示相册入口由系统实现决定。

### Android 原生反馈

```kotlin
val preview = ScannerPreviewView(activity, onFailure = ::showFailure, onResult = ::handleRawText)
preview.setFeedbackEnabled(true) // 和原宿主 BeepManager 一致：声音 true，振动 false
preview.setFeedbackEnabled(true, vibrateEnabled = true) // 仅宿主明确需要时开启振动
preview.setScanFrameSize(frameSizePx)
preview.setRunning(running)
preview.release()
```

构造签名和默认关闭反馈保持兼容。启用反馈时 context 必须可解析到 Activity；组件使用上游 BeepManager，
不复制声音文件或播放引擎。一次有效结果在停止预览后只反馈一次，旧代次/暂停/释放后的回调不反馈。
声音/振动异常不丢失有效二维码；短音 MediaPlayer 沿用 ZXing 的 completion/error 释放，manager 只持 application context。
宿主删除 `BeepManager` 与 `playBeepSoundAndVibrate()` 调用，其状态栏样式/恢复逻辑保留。

### OHOS Renderer 注册与生命周期

```typescript
import { GycScannerPreviewView } from '@gycrosskit/scanner-native';
// 使用当前 Renderer 的 View creator register map。
const name = GycScannerPreviewView.VIEW_NAME; // 'GycScannerPreviewView'
// map.set(name, () => new GycScannerPreviewView());
```

Native props：`running: boolean`、`scanFrameSize: number`（vp）、`onResult({value})`、`onFailure({message})`。
原生 View 自建 XComponent Surface；取景框由宿主绘制。有效码要求其像素矩形中心经当前 UIContext.px2vp 后
位于宿主给定方形框；无矩形时沿用 ScanKit 返回。未知帧 rescan，失败走 onFailure，不映射为取消。

`running=false` 对应相册/暂停/后台；surface 关闭或 View onDestroy 都排队 stop/release，销毁先清回调。
所有实例共享唯一 customScan owner/队列。旧会话开始释放就撤销其帧代次，stop/release 等待中不能交付旧帧；
成功 release 后才可转移 owner。stop 失败仍尝试 release；release 失败保留 owner，下一次启动重试，禁止叠加相机。
同步 start callback、重复帧、旧 View late callback、尺寸改变和迟到的释放不会覆盖后续相册或导航结果。

### Kuikly 类型化 View

```kotlin
import io.github.gycrosskit.scanner.kuikly.ScannerPreview

ScannerPreview {
    attr {
        size(width, height)
        scanFrameSize(frameSizeVp)
        running(cameraAllowed && foreground)
    }
    event {
        onResult { rawText -> /* 宿主验证/导航 */ }
        onFailure { reason -> /* 宿主文案/重试 */ }
    }
}
```

`ScannerPreviewView.NAME` 与 Renderer 的 `GycScannerPreviewView.VIEW_NAME` 相同。事件安全解析 JSONObject/JSON String；
畸形值不抛到原生相机回调。Compose 宿主沿用自己的 `MakeKuiklyComposeNode(factory = ::ScannerPreviewView, ...)`，
通过 `getViewAttr().running/scanFrameSize` 与 `getViewEvent().onResult/onFailure` 装配，不再声明私有 View 类型或 JSON parser。
组件无需引入 Kuikly Compose plugin/依赖；图片解码继续使用既有 `ScannerModule`，没有第二个图像桥。

宿主删除 `AppScannerPreviewView.ets` 的原生主体和 ScannerPreview.kt 中私有 DeclarativeView/事件 parser，
只留布局、rememberUpdatedState、当前 running 的业务门禁、框 UI 与权限/相册。Android/iOS 现有预览行为不变。
