# scanner 0.1.5 远程发布验收

## 发布范围

Maven `scanner-core` / `scanner-kuikly` 预发行 `0.1.5`，公开 API 保持兼容。Kuikly 后台取消将 pending/callback 清理派回调用时的页面 dispatcher，移除后清空 callbackRef，防止注册期间取消的重复注销；保留 disposed 和迟结果消费校验。

`decode`、`scanCode` 和 `dispose` 必须在所属页面 Kuikly Context 调用，页面 dispatcher 不能由 Default/IO/Unconfined 替代。清理不依赖已取消的 Job。

原生 HAR/Swift 源码未变，分别保持 `0.1.3` / `0.1.1`。旧渠道验收只适用于对应历史版本，不作为本版本的验收结果。

## 独立消费与运行边界

首次独立 Android consumer 在依赖解析阶段失败：Eazy 先提供 Kuikly metadata，随后同坐标 AAR 的 HEAD 返回 404。Tencent `maven-tencent` 对同坐标 GET 返回 200，文件 hash 与 metadata 一致；Eazy 稍后 GET/HEAD 也返回 200，因此该次失败不能解释为永久缺包或本次组件版本缺陷。

复验固定 `com.tencent.kuikly-open` group 使用 Tencent `maven-tencent` 的 exclusiveContent，避免其他镜像先提供 metadata 却暂时无法返回产物；其他 SDK/插件仓库顺序不变。尚未把本次失败写成构建或最终链接通过，复验结果由协调者补齐。

独立远程消费：通过。隔离组件文件与 descriptor 缓存后仅从 JitPack 下载精确版本；Android APK、D8、重复类及版本检查通过；iOS arm64/x64 编译、Simulator static Framework 导出与实际链接、版本检查通过；OHOS 五个组件 core/kuikly 编译及版本检查通过，live 不包含 OHOS 实现。Kuikly 使用腾讯 Maven 的专用 group 路由。没有本地源码、composite、mavenLocal 或 staging 替代远程制品。

本轮未进行生产宿主替换、Android/iOS/OHOS 真机或业务运行验收；源码编译、JVM fixture 与远程文件审计分别只证明对应边界。
